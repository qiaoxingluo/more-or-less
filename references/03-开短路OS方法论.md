# 开短路（OS / Open-Short）测试方案对比与选型

> 平台语境：ST2500 / ST2516 + SE-GIB100 通用器件接口板
> 参照：加速科技课件 `7.课件-测试案例-数字译码器（CD4511）`、工程样例 `CD4511_v1`
> 2026-10-28

---

## 一、OS 在测试流程里的定位

OS 永远排在第一个测试项，原因只有三条，但每条都很硬：

| 目的 | 说明 |
|---|---|
| 保护测试机 | 一个对 GND 短路的引脚，若在后续 FUNC 里被数字通道驱动到高电平，会灌大电流打坏 pin electronics 或烧 DPS。OS 先把这类器件拦下来。 |
| 停止浪费时间 | 打线没接上的芯片，后面的 IDD / VOH / VOL / FUNC / AC 全是废数据，跑得越晚亏得越多。 |
| 自身诊断 | 探针卡脏了、测试座针脚歪了、自焊线掉了，在工程上统统表现为"某几根脚开路"。**OS 是 TE 定位治具问题的第一抓手**，单次 CP/FT 良率暴跌先看 OS 分布。 |

## 二、物理前提：不是所有引脚都有那两个二极管

教科书方案的前提是「每个 IO 脚内部有一对首尾相接的 ESD 保护二极管，上接 VDD、下接 GND」。

⚠️ 这个前提**不是普遍成立的**，有几类例外：

| 例外情况 | 后果 |
|---|---|
| RF / 高速串行引脚 | 二极管的寄生电容会劣化高频性能，**常常刻意不接**。做 VNA 与去嵌时遇到的就是这类结构。 |
| 5 V tolerant I/O | 靠 NMOS 堆叠承受高压，若保留传统上二极管会导致漏电或闩锁风险，**常常没有到 VDD 的上二极管**。 |
| 部分模拟专用脚、高压脚 | 内部结构不同，OSP 的限值需要单独定，甚至不能用静态法。 |
| 老款双极型器件（如 74**LS**138） | TTL 输入是发射极结构，不存在标准的 VCC 侧二极管。 |

这直接导出两条工程规矩：

1. **OS 条件必须按引脚分组定制**，不是所有脚共用一套。缺失上二极管的脚只跑 OSN。
2. **任何芯片开跑前，先拿一颗已知良品（Golden Sample）确认 14 个脚的读数都在窗口里**。这一步省了，后面全是假失效。

## 三、五种方案逐个说

### 方案 1：串行静态（Serial PMU FIMV）

每根引脚单独加电流，其余全部接地。

- 做法：被测脚灌/抽 ±100 µA 并测电压，其余脚由 PMU 强制 0 V。
- 优点：能定位到具体哪根脚，也能抓 **pin-to-pin 相邻短接**。
- 缺点：时间是 ×N。14 脚 × 2 方向 = 28 次测量，每次还要 1 ms 以上建立延时。
- 适用：**引脚少（< 10）、工程调试、失效分析**。

### 方案 2：并行静态（Parallel PPMU FIMV）—— 课件标准方案

除 GND 外所有脚同时加电流、同时测量。**这就是 CD4511_v1 工程采用的做法**（`ppmu.Signal("INOUT_PINS")`）。

- 优点：只要 1~2 次测量，最快。
- 缺点：**完全抓不到相邻引脚短接**。
- 适用：管脚数多、量产为主的组织化器件。

#### 为什么抓不到？（这是最容易被忽略的一段）

两根相邻脚短接时：

- 每台 PPMU 仍在各自抽 100 µA → 短接节点总共要流走 **200 µA**；
- 该节点上有 **两只并联的下二极管**，200 µA 平均分流，每只还是 100 µA；
- 二极管正向压降是电流的**对数**函数——电流没变，Vf 就基本不变；
- 于是两只脚都读到正常的 −0.65 V，**双双 PASS**。

注意：**调紧限值也救不了**，因为读数根本没有偏移。这是一个原理级盲区，不是参数级问题。

### 方案 3：双轮奇偶法（Odd/Even Two-Pass）—— 性价比最优

业界的折中方案。第一轮测奇数脚、偶数脚强制接地；第二轮反过来。

关键在于它把"分流"变成了"硬短路"：

- 引脚 1、2 短接时，第一轮里 2 号脚被强置 0 V；
- 加到 1 号脚上的 100 µA 直接经短接点灌进地 → 读数被拉到 **≈ 0 V**；
- 0 V 远低于下限 −0.2 V，**硬 FAIL**，两根脚的序号也同时暴露出来。

⚠️ 分组必须按**物理相邻关系**，不能按信号名顺序：

- DIP / SOP / TSSOP：管脚编号即物理顺序，奇偶分组天然保证相邻脚异号 ✓
- **BGA / QFN**：必须按物理坐标分组，否则同一个底下面的两个球可能同号。

### 方案 4：数字源跑 OS Pattern + PMU 串行兜底 —— 量产最优

先用数字通道跑一段 OS pattern（借 VREF 建立动态负载电流）做并行筛查，pattern 失败再掉到 PMU 串行逐脚定位。

- 优点：绝大多数器件在第一段 pattern 就 PASS 出去了，只在失效时才付串行的时间代价。**平均耗时最低。**
- 代价：**画 DUT 板（loadboard）时必须同时把数字源和模拟源都分配到各脚**，这是硬件阶段就要决定的事，事后改不了。

### 方案 5：电容 / 电荷法 —— 用于没有二极管的引脚

对 RF 脚、5 V tolerant IO 这类无 ESD 二极管的引脚，静态二极管法失效，改用：

- 向引脚灌一个小电流脉冲，测量电压上升斜率或直接测最终电压：开路时只对寄生电容 C 充电、电压迅速冲到钳位；有正常结构时被钳在特征电压附近；
- 或直接测量引脚对地电容是否在预期范围内；
- 也可以退一步：该脚只跑单方向（OSN），把保护结构的验证交给下游的 Leakage / FUNC / ESD 抽检验。

## 四、成本 vs 覆盖对照表（以 14 个信号脚为例）

| 方案 | 测量次数 | 抓开路 | 抓对 GND/VCC 短接 | 抓相邻脚短接 | 适用 |
|---|:--:|:--:|:--:|:--:|---|
| 串行静态 | 28 | ✓ | ✓ | ✓ | 调试 / 失效分析 |
| 双轮双方向 | 4 | ✓ | ✓ | ✓ | **脚数少，推荐** |
| 双轮单方向（OSN） | 2 | ✓ | ✓ | ✓ | **推荐，性价比最高** |
| 并行双方向 | 2 | ✓ | ✓ | ✗ | 课件 CD4511 方案 |
| 并行单方向 | 1 | ✓ | ✓ | ✗ | 极限量产 |
| 数字 Pattern + 串行兜底 | 1 段 pattern | ✓ | ✓ | ✓ | 大批量，需预先布好双源 |

**这里有个反直觉但很好用的结论：**

> 课件用的「并行双方向」要 2 次测量；而「双轮单方向」也要 2 次测量，却能额外覆盖相邻脚短接。
> **同样的测试时间，换成双轮单方向是纯赚的。**

（代价是不再验证上二极管。但对 CMOS 器件来说，上二极管缺失很少是致命缺陷，通常交给 Leakage / ESD 抽检。）

## 五、限值怎么定：这不是数据手册参数

这是最常见的作业/新人错误——**把 0.2 / 1.2 当成规格书数字抄过来**。

翻遍各家资料，窗口本身就不统一：

| 来源 | 下限 | 上限 |
|---|---|---|
| 加速科技 ST2500 手册 / `CD4511_v1.tmf` 工程 | 0.2 V | 1.2 V |
| 通用业界口径 | 0.2 V | 1.5 V |
| 期刊《基于 ATE 的 IC 测试原理、方法及故障分析》 | 0.1 V | 1.2 V |
| **课件 PPT `7.课件（CD4511）` 第 15 页** | 0.2 V | **0.8 V** |

⚠️ **注意最后一行**：同一门课，PPT 讲稿写 0.8 V，随 `'CD4511_v1'` 工程下发的 `.tmf` 里写的却是 1.2 V。**实际以工程文件为准**——0.8 V 上限会把 Vf 偏高但完全正常的管子误杀。

正确做法（限值不是查出来的，是**标定**出来的）：

1. 先放宽窗口（如 0.05 ~ 1.8 V），跑 30~50 颗已知良品；
2. 统计每个 φ 的均值 μ 和标准差 σ，收紧到 **μ ± 6σ**；
3. 叠加 GR&R（设备复现性）余量；
4. 再跑故意开路的坏品（如挑掉一根线的 Sample），确认**良品簇与失效簇之间有清晰间隔**才定稿。

另外两个必须记住的量：

- **电压钳位必须设在窗口之外**（通常 ±2 V）。钳位设成 ±1.2 V 的话，开路的读数就落在窗口边界上，判不出来了。
- **电流别超过 ~100 µA**。OS 是真的让 ESD 二极管正偏导通，电流过大可能损伤器件，这也是业界普遍取 100 µA 的原因。

## 六、六条容易踩的坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **VCC 必须强置 0 V** | OS 的上二极管回路要靠 VCC 这条低阻通路构成。VCC 悬空时，全好的芯片 OSP 也会读到钳位电压，表现为"整批开路"。这是 `CD4511_v1` 里 `dps.Signal("VDD").SetMode("FVMV").VoltForce(0)` 那行的全部意义。 |
| 2 | **GND 不走 ATE 通道** | HC138 的 GND（8 脚）直接硬线接接口板系统地，`SE-GIB100` 上用的是 **b7 针脚的 GND**，注意别接到 AGND（b2/b5/b12/b17/b23/b28）——那是模拟地，不是同一个网络。 |
| 3 | **电源脚不能被当成普通 IO 测** | 内部结构不同，标准 OS 限值不适用。不过好在：VCC 脚若开路，所有上二极管测试会集体失效；GND 脚若开路，所有下二极管测试会集体失效——**症状本身就是诊断信息**。 |
| 4 | **板上的上拉电阻会污染结果** | I²C 类的 SDA/SCL 会上拉到 VCC。做 OS 时 VCC 被拉到 0 V，上拉电阻会把被测脚拽向地，读数和 Vf 会偏。课件 HK24C02 案例明确提到要用继电器物理断开。HC138 没有这类上拉，但自焊线板上如果自己加了，要同步考虑。 |
| 5 | **温度漂移** | 二极管 Vf 约 **−2 mV/°C**。25 °C→85 °C，标称 0.65 V 会跌到约 0.53 V，仍在 0.2~1.2 窗口内，余量够。但如果把下限提到 0.5 V 以上，高温就一定会误杀。 |
| 6 | **采样前必须留建立延时** | `Measure()` 前必须有 `sys.DelayUs(5000)`。去掉延时读到的是瞬态，数据会飘，`±6σ` 标定会直接失败。 |

## 七、针对 ST2500 + 74HC138 的建议

74HC138 是标准 CMOS，14 个信号脚都有完整的上下二极管，方案 1/2/3/4 全部适用。结合你的实际情况（**自焊线的通用接口板**）：

- 「相邻脚短接」在这个场景下的真实成因是**焊盘连锡 / 杜邦线相碰**，概率不低，不是可以忽略的尾部风险；
- 但 14 个脚也不至于让串行法慢到不能接受。

**推荐：方案 3「双轮奇偶法」，两个方向都做（4 次测量）。**

理由：相对课件方案只多 2 次测量（各自几毫秒），就把自焊线场景里最高发的失效类型覆盖住了；同时保留双方向，万一某个脚结构上没有上二极管，也能第一时间发现而不是漏过去。

配套工程已生成在 `outputs/HC138_OS_V1/`（当前实现的是课件标准并行方案，可直接扩展gruppen为奇偶两组）。

## 八、待确认事项

1. 实物丝印究竟是 `74HC138` 还是带厂商前缀（`SN74HC138N` / `MC74HC138` / `TC74HC138`）？—— 引脚定义一致，流程通用。
2. 若为 **74LS138（TTL）而非 74HC138（CMOS）**：TTL 输入没有标准 VCC 侧二极管，OSP 会全体读到钳位电压，必须改为**只跑 OSN**，并相应重定限值。
3. 测试环境温度是否需要覆盖到高温？若是，标定必须在高温箱里重跑一遍。
