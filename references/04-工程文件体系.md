# ST2500 工程文件体系（逐文件格式）

> 母文档：`SKILL.md` 第 5、6 节。本文件给出每种文件的**真实格式样例**（取自 CD4511_v1）。

---

## 0. 文件清单与依赖

```
<工程名>.job ──┬─ <工程名>.res    资源（板卡与通道数）
               ├─ <工程名>.sig    信号→通道映射
               ├─ <工程名>.grp    信号分组
               ├─ <工程名>.tim    时序（WFT）
               ├─ <工程名>.pat    pattern 索引
               │   └─ pattern/*.csv  向量真值表
               ├─ <工程名>.tmf    测试流程 + Limits + Bin
               └─ Test.cpp ─(Makefile)→ Test.dll
```

`.job` 是唯一入口，其余全部由它索引。缺任何一个文件工程都无法加载。

## 1. `.res` —— 资源定义

CSV，**每块板卡一组**，最后一行为 OffLine 占位：

```csv
1,OnLine,AWG_1,AWG,1
,,DGT_1,DGT,1
,,RVS_1,RVS,1
,,DPS_1,DPS,4
,,BPMU_1,BPMU,4
,,CBIT_1,CBIT,8
,,DIO_1,DIO,32
2,OnLine,AWG_2,AWG,1
,,DGT_2,DGT,1
...
4,OnLine,AWG_4,AWG,1
,,DGT_4,DGT,1
,,RVS_4,RVS,1
,,DPS_4,DPS,4
,,BPMU_4,BPMU,4
,,CBIT_4,CBIT,8
,,DIO_4,DIO,32
5,OffLine,,,
```

列含义：`板卡序号, 在线状态, 实例名, 资源类型, 通道数`

⚠️ 改硬件配置（如换一块板卡）必须同步改这里，否则 `.sig` 里引用的通道会查不到。

## 2. `.sig` —— Signal Map

```csv
SigName,AFEType,ChType,Site0_CH
"VDD",DPS,Supply,1:1:0
"A",DIO,Inout,1:1:0
"B",DIO,Inout,1:1:1
"C",DIO,Inout,1:1:2
"D",DIO,Inout,1:1:3
"Ya",DIO,Inout,1:1:4
...
```

| 列 | 含义 |
|---|---|
| SigName | 信号名，代码中 `Signal("xxx")` 引用的就是这个 |
| AFEType | 模拟前端类型：`DPS` / `DIO` |
| ChType | `Supply`（电源）/ `Inout`（双向） |
| Site0_CH | `板号:组号:通道号` |

**映射要点：**
- VDD 用 DPS 通道 `1:1:0`；
- 信号脚用 DIO 通道，**从 `1:1:0` 开始连续分配**（与第 5 组板卡 index 不冲突即可）；
- **GND 不出现在 `.sig` 里** —— 它硬接线到系统地，不占 ATE 通道。

## 3. `.grp` —— Signal Group

```csv
GrpName,SigName
"INPUT_PINS",A,B,C,D
"OUTPUT_PINS",Ya,Yb,Yc,Yd,Ye,Yf,Yg
"INOUT_PINS",A,B,C,D,Ya,Yb,Yc,Yd,Ye,Yf,Yg
```

**为什么要分组？**

代码里对组下一条命令 = 并行作用于该组所有管脚：

```cpp
ppmu.Signal("INOUT_PINS").SetMode("FIMV").CurrForce(-100e-6).Execute();
// ↑ 一句，7 个脚同时动 —— 这就是并行 OS 快的根本原因
```

若要升级为双轮奇偶法，这里再加两行：

```csv
"ODD_PINS",A,C,Ya,Yc,Ye,Yg
"EVEN_PINS",B,D,Yb,Yd,Yf
```

（分组依据是**物理相邻**，不是信号名顺序 —— 详见 `03` 第 3 节）

## 4. `.tim` —— Timing / WFT

CSV 格式：**每个信号 × 每个逻辑值一行**。

```csv
TimingName,Period,Signal,WFC,Evt0 Event,Evt0 Expr,Evt1 Event,Evt1 Expr,Evt2 Event,Evt2 Expr,Evt3 Event,Evt3 Expr
WFT1,10us,INPUT_PINS,0,D,0us,,,,,,
,,,1,U,0us,,,,,,
,,OUTPUT_PINS,L,L,9us,,,,,,
,,,H,H,9us,,,,,,
,,,X,X,9us,,,,,,
```

| 列 | 含义 |
|---|---|
| TimingName | 波形格式表名，pattern 里通过 `WFT` 列引用 |
| Period | 周期，如 `10us` |
| Signal | 信号名或组名 |
| WFC | Waveform Character，逻辑值：`0` `1` `L` `H` `X` |
| Evt0~3 | 事件（D=Drive / 比较沿）及其时间表达式 |

**这张表告诉我们的：** CD4511 案例用 10 µs 周期，输入在 0 µs 驱动，输出在 **9 µs**（周期末）比较 —— 留了 9 µs 让输出建立。

**四种输入格式**（NRZ / RZ / RO / SBC）通过 Evt 表达式区分，见母文档第 7 节。

## 5. `.pat` 与 `pattern/*.csv`

`.pat` 是索引：

```csv
1,,FUNC,1001,true,.\pattern\func.csv,
```

字段：序号, (空), Pattern名, 编号, 使能, 相对路径, (空)

`pattern/func.csv` 是真值表：

```csv
Label,WFT,Sequence,LE,BI,LT,D,C,B,A,Ya,Yb,Yc,Yd,Ye,Yf,Yg,
,WFT1,nop,0,1,1,0,0,0,0,H,H,H,H,H,H,L,
,WFT1,nop,0,1,1,0,0,0,1,L,H,H,L,L,L,L,
,WFT1,stop,0,1,1,0,0,1,0,H,H,L,H,H,L,H,
```

- 前几列是控制列（Label / WFT / Sequence / LE / BI / LT），之后**每列一个信号名**；
- 输入列填 `0` `1`，输出列填 `L` `H` `X`（期望值）；
- `Sequence` 最后一行为 `stop`。

## 6. `.tmf` —— 测试流程 + Limits + Bin

JSON，**带 BOM（utf-8-sig）**。

### 6.1 两个必踩的坑

⚠️ **坑一：FuncList 不在顶层**

```
data["FuncList"]                    → None ❌
data["SiteList"][0]["FuncList"]     → 列表 ✅
```

递归遍历才找得到的路径，值得记牢。

⚠️ **坑二：必须 `encoding='utf-8-sig'`**

```python
json.load(io.open(path, encoding='utf-8-sig'))   # ✅
json.load(io.open(path, encoding='utf-8'))       # ❌ BOM 导致解析失败
```

### 6.2 结构

```
{
  "ChangeDate": "...", "Version": "V1.0",
  "ProjectInitName": "ProjectInit",
  "ProjectResetName": "ProjectReset",
  "ProjectReuseName": "ProjectReuse",
  "SiteList": [
    {
      "SiteNumber": 0,
      "SiteInitName": "site_init", "SiteResetName": "site_reset",
      "LoopCount": 1, "ErrorSbin": 999, "ErrorHbin": 999,
      "BinLoopCount": 1,
      "FuncList": [
        {
          "FuncNumber": 0, "FuncName": "OSN_T", "FuncDesc": "...",
          "LoopCount": 1, "Sbin": 2, "Hbin": 2,
          "Results": ...,
          "ResultAnalysis": [
            { "ParamName": "A0", "ParamNumber": 1,
              "Min": -1.2, "Max": -0.2, "Unit": "V" }
          ]
        }
      ]
    }
  ]
}
```

### 6.3 关键约定

- **`FuncName` 必须与 `Test.cpp` 里的导出函数名逐字一致** —— Runner 按函数名调用；
- **`ResultAnalysis` 的参数顺序必须与 `Measure()` 返回的数组顺序一致**，否则判错脚；
- **`Sbin`（软件 Bin）与 `Hbin`（硬件 Bin）** 用于把失效器件分流归类，`SetPassBin` 用 `Sbin=1 / Hbin=1`；
- `ErrorSbin / ErrorHbin` 是**程序异常**（非测试失败）时的归 bin。

### 6.4 现成工具

```bash
python scripts/tmf_dump.py <目录>       # 打印所有工程的 FuncList
python scripts/tmf_dump.py <目录> -v    # 附带每项的 Min/Max/Unit
```

## 7. `Test.cpp` / `Makefile` / `interface.h`

### 7.1 interface.h

```cpp
#define USER_CODE extern "C" __declspec(dllexport)
#include "usrInterface.h"
#include "usrDataType.h"
```

### 7.2 Test.cpp 骨架

```cpp
#include "interface.h"
unsigned long SITE = 0, SITE_ID = 0, ACTIVE_SITE_NUM = 0;

USER_CODE void ProjectReuse()  { /* 工程复用时 */ }
USER_CODE void ProjectInit()   { /* 工程启动 */ }
USER_CODE void ProjectReset()  { /* 工程复位 */ }
USER_CODE void site_init()     { /* site 初始化 */ }
USER_CODE void site_reset()    { /* site 复位 */ }

USER_CODE void OSN_T() {
    TEST_BEGIN
    // ... 测试逻辑
    TEST_ERROR
    binObj.HandlerException(0);
    TEST_END
}
```

**三条铁律：**

1. **没有 `main()`** —— Runner 按 `.tmf` 的 FuncList 顺序按名字调用导出函数；
2. **每个测试函数必须包 `TEST_BEGIN` / `TEST_ERROR` / `TEST_END`** —— 缺了异常分支时一旦报错，DUT 会停在带电状态，有硬件损伤风险；
3. **每个函数结尾必须复位** —— 把 DPS 与 PPMU 回到 0 V 并 `DisConnect()`，否则下一个测试项继承上一项的偏置。

### 7.3 Makefile

```makefile
RUNNER_HOME = d:/MINI-ATE\runner
LIBS = ... -L$(RUNNER_HOME) -lproject -lTester -lBinDef -lUsrApi -lWaveCalc -lShmoo
all:
	g++ -g -std=c++17 $(SRC) $(INCS) $(LIBS) $(CFGOPT) -DINTERFACE_EXPORTS -o Test.dll
```

- **必须 `-DINTERFACE_EXPORTS`**，否则导出符号不对；
- 输出固定是 `Test.dll`；
- `RUNNER_HOME` 指向测试机 runner 目录，路径不存在会直接报错。

## 8. 标准开发流程（五步，不可乱序）

| 步 | 改什么 | 为什么是这个顺序 |
|:--:|---|---|
| 1 | `.sig` Signal Map | 先确定每个脚接哪个通道，后面全部依赖它 |
| 2 | `.grp` Signal Group | 分组是并行操作的前提 |
| 3 | 新建 `.tim` Timing | 时序决定驱动/比较沿，pattern 依赖它 |
| 4 | 编辑 `.tmf` | 流程与 bin，函数名要与 cpp 对齐 |
| 5 | 定 Limit | 限值最后定 —— 因为要靠实测标定（见 `07`） |

> ⚠️ 反过来做会反复返工：先写 cpp 再改 sig，等于每次改通道都要重写 cpp。
