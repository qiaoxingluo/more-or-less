# 官方五款案例的测试流程详解

> 数据全部由 `scripts/tmf_dump.py` 解析真实 `.tmf` 得到，**非推测**。
> 源目录：`3.程序案例/2.半导体工程师实训平台—五款案例/`

---

## 0. 命名约定

| 后缀 | 含义 | 阶段 |
|---|---|---|
| **FT** | Final Test | 封装成品测试，handler 上料 |
| **CP** | Circuit Probe | 晶圆级探针测试，prober 步进 |

`.tmf` / `.sig` / `.pat` 结构对两者完全一致，差别在上位机 runtime 由 prober / handler 提供相应钩子（`ProjectInit` 里 `EnableWaferEndCheck` / `EnableLotEndCheck`）。

> 本目录里的 `ADC0832`、`HK32F031F4P6`、`LM358P`、`TPS73625` 是 FT，`HK24C02` 是 CP1。

## 1. ADC0832（8 位串行 ADC，FT）

```
FN0  OS_TEST          13 参数
FN1  ADC_Static_AWG    6 参数
FN2  ADC_Dynamic_DSIO  4 参数
FN3  SetPassBin
```

### OS_TEST（13 个参数）

```
OSN_CS, OSN_CH0, OSN_CH1, OSN_DI, OSN_DO, OSN_CLK, OSN_VCC_DIO
OSP_CS, OSP_CH0, OSP_CH1, OSP_DI, OSP_DO, OSP_CLK
```

⚠️ **注意这个不对称**：OSN 有 7 项（含 `OSN_VCC_DIO`），OSP 只有 6 项 —— **VCC 脚只有 OSN，没有 OSP**。

这正是「坑 3：电源脚不能被当成普通 IO 测」的官方实证。

### ADC_Static_AWG（6 个参数）

`Offset, Gain_Error, Miss_Code, DNL, INL, ADC_OUT_Lin`

AWG 送斜坡 → 逐码采样 → 统计码密度算出 DNL / INL / 失码。

### ADC_Dynamic_DSIO（4 个参数）

`SNR, SINAD, THD, ENOB`

AWG 送纯正弦 → DSIO（数字源/IO）采样 → FFT 分析。

> ENOB 由 SINAD 推出：$ENOB = (SINAD - 1.76)/6.02$

## 2. HK24C02（I²C EEPROM，CP）

```
FN0  OS            os_icc, OS_SCL, OS_SDA
FN1  leakage       leak_sda_H, leak_scl_H, leak_sda_L, leak_scl_L
FN2  standby       静态电流
FN3  WRITE_55AA_HV TM_ALLEVEN_55_2K, TM_ALLODD_AA_2K
FN4  READ_55AA_HV  回读校验
FN5  SetPassBin
```

### 关键看点 1：只有 2 个信号脚的 OS

I²C 只有 SCL / SDA 两个脚，加 VCC 的 `os_icc` 一共 3 个参数。

⚠️ 这两个脚**必然有板上上拉电阻** → 必须先用 CBIT 继电器断开，否则 OS 读数被拖偏（坑 4）。这是唯一一个必须在 Test.cpp 里额外处理继电器的案例。

### 关键看点 2：WRITE_55AA_HV 就是 MBIST 图样

`TM_ALLEVEN_55_2K`：向**全偶数地址**写 `0x55`
`TM_ALLODD_AA_2K`：向**全奇数地址**写 `0xAA`

```
地址:  0     1     2     3     4     5    ...
数据: 0x55  0xAA  0x55  0xAA  0x55  0xAA  ...
```

这是**棋盘 / 交替图样**（Checkerboard / Alternating Pattern），覆盖：

- **地址译码故障**（写 A 地址却落到 B 地址）；
- **相邻单元耦合故障**（写一个单元把邻居带翻）。

2K = 该 EEPROM 的 2 Kbit 容量，全地址空间覆盖。

### 流程逻辑

```
OS → leakage → standby(功耗)
   → WRITE(55/AA 图样) → READ(回读比对) → SetPassBin
```

## 3. HK32F031F4P6（Cortex-M0 MCU，FT）—— 项数最多

```
FN0   OSN_TEST    17 pins     FN7   HSE_TEST    外部高速晶振
FN1   OSP_TEST    17 pins     FN8   PVD_TEST    电源监视 (3 参数)
FN2   VOH_TEST                FN9   BIST_TEST   内建自测试
FN3   VOL_TEST                FN10  HSI_TEST    内部高速 RC
FN4   VOPD_TEST   15 pins     FN11  PLL_TEST    锁相环
FN5   VOPU_TEST   15 pins     FN12  LSI_TEST    内部低速 RC
FN6   NFL_TEST    2 参数      FN13  SetPassBin
```

### MCU 类测试的三层结构

| 层 | 测试项 | 测什么 |
|---|---|---|
| **引脚层** | OSN / OSP / VOH / VOL | 每个 GPIO 的物理连接与驱动能力 |
| **GPIO 结构层** | VOPD / VOPU / NFL | **内部**下拉电阻、**内部**上拉电阻、噪声滤波 |
| **芯片内部层** | HSE / HSI / PLL / LSI / PVD / BIST | 时钟源、PLL、电源监视 —— **无法从外部引脚直接测** |

### 为什么 MCU 最难测

内部模块（RC 振荡器精度、PLL 锁定、PVD 阈值）**没有对外的物理引脚**。只能通过：

1. 让芯片进入特定测试模式（通过 NRST / BOOT0 引脚序列）；
2. 让内部 BIST 电路自检；
3. 或把内部信号引到某个 GPIO 上输出，再用 ATE 测频率。

FN0/FN1 的 17 个脚：`PA0~PA7, PA9, PA10, PA13, PA14, PB1, BOOT0, PF0, PF1, NRST`
注意 **PA8 / PA11 / PA12 不在列表里** —— 大概率被晶振或 USB 占用，这属于按芯片手册裁剪的正常做法。

## 4. LM358P（双运放，FT）

```
FN0  Ios_Uos_TEST   Uos, Ios
FN1  CMRR
FN2  Aus
FN3  PSRR
FN4  icc            ic, ic1
FN5  SetPassBin
```

| 参数 | 含义 | 廉价运放 | 精密运放 |
|---|---|---|---|
| **Uos** | 输入失调电压 | mV 级 | µV 级（激光修调） |
| **Ios** | 输入失调电流 | 几十 nA | pA 级 |
| **CMRR** | 共模抑制比 | 60~70 dB | 100 dB+ |
| **Aus** | 开环电压增益 | 低 | 高 |
| **PSRR** | 电源抑制比 | 差 | 好 |
| **icc** | 静态功耗电流 | — | — |

💡 **这五个参数就是「两毛钱运放 vs 二十块钱运放」的全部差距。**

用万用表和示波器**分不出来** —— 失调只有几 mV，被示波器底噪淹没。只有 ATE 的Force/Measure 能力才能在 µV / pA 量级上定量拉开差距。这也是为什么运放 datasheet 上那些漂亮的数字，只有 ATE 能验证。

## 5. TPS73625（LDO 线性稳压器，FT）—— 推荐的教学首选

```
FN0  OS_TEST      IN, OUT, EN
FN1  VOUT_TEST    6 组条件
FN2  LNR_TEST     Line_Regulation   线性调整率
FN3  VDO_TEST     Vdrop             压差
FN4  LDR_TEST     LDR_1MA, LDR10MA  负载调整率
FN5  ICL_TEST     ICL               限流点
FN6  IGND_TEST    Ignd_10mA, Ignd_400mA  静态/地电流
FN7  PSRR_TEST    PSRR_100HZ, PSRR_10KHZ
FN8  SetPassBin
```

### VOUT_TEST 的 6 组条件 —— 典型的交叉 Test Condition

```
VIN2_7V_10MA      VIN 2.7 V,  IOUT 10 mA
VIN4V_10MA        VIN 4 V,    IOUT 10 mA
VIN2_5V_10MA      VIN 2.5 V,  IOUT 10 mA
VIN2_7V_400MA     VIN 2.7 V,  IOUT 400 mA
VIN4V_400MA       VIN 4 V,    IOUT 400 mA
VIN5_5V_400MA     VIN 5.5 V,  IOUT 400 mA
```

**3 种输入电压 × 2 种负载电流**。这就是 ATE 相比手工测试的核心价值 —— 在多个工作点（corner）上自动重复同一套判据。

### 为什么推荐它当入门案例

| 优点 | 说明 |
|---|---|
| **不需要写 Pattern** | 纯 DPS + PMU 组合，不用处理时序和向量 |
| **每项对应 datasheet 一项** | VOUT / LNR / LDR / VDO / IGND / PSRR / ICL 全是标准 LDO 规格 |
| **物理意义直观** | 「输入电压变了输出漂多少」这种问题，一眼就懂 |
| **对 Test Condition 要求高** | 恰恰锻炼了最容易忽视的能力：条件怎么设、先设哪个、要不要延时 |

> 缺点也明显：学不到 Pattern / Timing / SBC 这些「真正的」数字测试内容。所以推荐路径是 **TPS73625 入门 → CD4511/HC138 练数字 → ADC0832 练混合信号 → HK32F031F4P6 练系统级**。

## 6. 综合：从零排一个测试流程的套路

```
① OS              保护机器 + 拦早期废品
② Leakage        确认没有栅氧/ESD 损伤
③ IDD Static     静态功耗，抓闩锁与内部短路
④ IDD Dynamic    动态功耗，抓只在翻转时才暴露的缺陷
⑤ VOH/IOH        输出带载能力（拉电流）
⑥ VOL/IOL        输出带载能力（灌电流）
⑦ VIL/VIH        输入阈值与噪声容限
⑧ Function       真值表 / Pattern / MEM 图样
⑨ SetPassBin     归良品 bin
```

**排序三原则：**

1. **OS 永远第一** —— 保护设备的同时避免给坏芯片浪费时间；
2. **先 DC 后 AC** —— 先确保每个脚电气连接 OK，再谈功能时序；
3. **便宜的先跑** —— 便宜的项能拦掉大部分废品，减少后面昂贵测试的调用次数。
